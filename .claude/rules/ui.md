# 画面を作る・直すときのルール（2026-10-22 利用者の指摘から作成）

CLAUDE.md 1章の「手段：とにかく簡単な入力と表示」を守るための決まり。毎回の指摘を繰り返させないために、指摘の傾向をここにまとめた。
画面の変更を見せる前と、`/code-review` の前に、下の「見せる前の確かめ」を全部通す。

## 1. 原則（利用者の指摘から）

1. **よく使うものを上・手前に、たまにしか使わないものは奥・下に。**
   - 実例：入力画面は「金額 → 数字キー → 分類」。「数字のがメモより大事」でメモ・日付は一番下（2026-10-21）。
   - 実例：残高合わせは「そんなにすごく使う機能じゃない」ので、財布を押した先の一番下（2026-10-21）。
2. **数字・合計は押せる。押すと中身（詳細）が出て、直す・返すなどの操作はその先に置く。**
   - 実例：財布の総額 → 財布の詳細 → 残高合わせ。貸し借りの残り → 一覧 →「全額返す」「一部返す」（2026-10-21）。
   - 合計だけ見せて終わりにしない（「合算されていると返しづらい」）。
3. **1つの作業は1画面で終える。スクロールさせない。**
   - 実例：入力画面が縦に長く、毎回スクロールが要った（2026-10-21）。iPhone SE（375×667）で収まること。
4. **余白は少なめ。情報を詰めて、一度に多く見せる。**（2026-10-21・2026-10-22 の2回指摘）
5. **操作中に画面を動かさない。** 押したところだけが変わる。開く動きの繰り返し・スクロール位置の戻り・拡大は不具合。
   - 実例：数字キーを押すたびにシートが開き直して揺れた（2026-10-21）。
6. **押す回数を減らす。** 決まっていることは自動で入れる（財布は分類から、日付は今日）。違うときだけ変える。

## 2. 使い回す正本（同じことを別に作らない）

| やること | 正本 |
| --- | --- |
| シートを描く（動きを繰り返さない・スクロールを保つ） | `app/js/main.js` の `layer.html` |
| 数字キー | `app/js/main.js` の `keys()` |
| 記録・相手・移動の呼び方 | `app/js/labels.js`（iPhone と PC で共通） |
| 色・余白・文字の大きさ | `app/style.css` の `:root` と、末尾の「余白を詰める」まとまり |

## 3. 見せる前の確かめ（全部通してから利用者に見せる）

- [ ] iPhone SE（375×667）で、作業の画面がスクロールなしに収まる（ブラウザで幅と高さを合わせて開き、`scrollHeight` を見る）
- [ ] 一番よく使う操作が一番上・一番押しやすい所にある。たまにしか使わないものは下か、押した先にある
- [ ] 出している数字・合計を押すと中身に行ける（行けないなら、行けない理由がある）
- [ ] 余白が前の画面より増えていない。説明文は1〜2行に収まっている
- [ ] 押しても画面が揺れない・先頭に戻らない（数字キーを続けて押して確かめる）
- [ ] 同じ意味の部品を新しく作っていない（2章）

## 4. 方針が変わったら、前に作った画面も合わせる

新しい画面だけ方針どおりにして、前の画面を古いまま残さない。方針に合わない既存の作りは、継ぎ足しで避けずに作りを変える（利用者 2026-10-22「既存のシステムがある場合も今の方針により沿って構造を変更した方がいい場合はそれを優先したい」）。
直す範囲が広いときは、理解確認で一覧にして見せてから直す。
