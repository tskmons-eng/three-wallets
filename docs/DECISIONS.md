# 仕様の判断（なぜそうしたか）

## 2026-10-21 データの置き場所とバックアップ

- データは iPhone の中。iCloud は使わない（利用者「アイクラウド嫌」）。
- バックアップは自社 XServer へ自動送信。車管理アプリの中には作らず、別の小さな受け口にする（車管理は進行中の作業が多く、混ぜると壊すおそれ。家計データを車両システムに混ぜない）。
- 送る前に端末内で合言葉により暗号化。サーバーには読めない中身だけ置く。合言葉を忘れると戻せない。
- 投資は入れた額・出した額のみ。評価額・株価は扱わない。

## 2026-10-21 v1.0.0 で決めた細かいこと

- 固定費は「登録した日の翌日以降」の分から自動で入る。入れた月は覚えておき、自動の記録を消しても入り直さない。
- 記録に使った分類は消さずに隠す（前の月の合計が崩れないように）。固定費が使っている分類は消せない。
- サーバーの受け口は、最初に送ってきた1つのバックアップIDだけを持ち主にする。合言葉を変えたいときはサーバーの allowed.txt を消してから設定し直す。
- 新しく始めるときに同じ合言葉のバックアップがサーバーにあれば、上書きせず引き継ぎに回す。
- アプリの部品は手元の分を先に出し、裏で新しい版を取る（電波が弱くてもすぐ開くため）。新しい版は次に開いたときに効く。

## 2026-10-21 v1.1.0 貸し借り

- 返すのも逆向きの貸し借りとして記録し、残りは「A→B − B→A」で毎回計算する（保存しない）。相手は財布か人（'p:名前'）。
- 移動＝あげたお金（役員報酬・つみたて）、貸し借り＝返すお金。どちらも支出・収入には数えない。
- 「人との貸し借りを含めると」＝財布の合計＋人に貸している分−人に借りている分。財布どうしの貸し借りは合計を変えない。
- 毎月の返済は固定費の行き先「貸し借り：〜へ返す」。残りより多くは返さず、返し終わった月は飛ばす（後で借り直しても、さかのぼらない）。

## 2026-10-22 v1.7.0 予算とお知らせ

- 予算は分類ごと（月）。分類に `budget`。8割で黄・超えたら赤。内訳の棒は予算があれば 使った÷予算。財布で絞っているときは出さない。
- お知らせ：予算（8割・超えた）、返す期限（7日前・過ぎた）、バックアップ（2日送れていない）。ホームの一番上に、あるときだけ。× で消したことは端末だけに覚え、状態が悪くなる（id が変わる）とまた出る。
- 返す期限は貸し借りの組ごとに `S.loanDue[pairKey]`。
- プッシュ通知は作らない（サーバーは中身を読めないため）。足りなければ考える。
- 不具合直し：新しい版を取るとき、ブラウザが覚えている古いファイルを混ぜていた（新しい main.js と古い calc.js で起動しない）。sw.js で cache: 'reload' / 'no-cache' を使う。

## 2026-10-26 v1.8.0 集計から追加・紐づけ

- 分類の中身に「＋〇〇で記録」（分類を選んだ状態で開き「〇〇で保存」）、財布の詳細に「＋〇〇の財布で記録」、中身に「前の月も見る」。
- 紐づけは①記録から始めるやり方（②案件を先に作るやり方と比べて利用者が選んだ。入力画面を変えないため）。記録に `link`（まとまりの印）を足すだけで、残金・内訳・予算などの計算は変えない。
- まとまりの出た・入った：支出・収入と、人との貸し借り。財布どうしは数えない。名前・終わりにした印は `S.groups`。1件だけになったまとまりは解く。
- 移動・残高合わせに直した記録は紐づけを外す。
